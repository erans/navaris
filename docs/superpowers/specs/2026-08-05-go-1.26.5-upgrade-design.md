# Go 1.26.5 Upgrade Design

## Goal

Upgrade Navaris from Go 1.26.1 to the latest stable Go 1.26 patch release, Go 1.26.5, and make local, CI, release, and container builds use that patch consistently.

## Current State

- `go.mod` declares Go 1.26.1.
- GitHub Actions workflows use `actions/setup-go` with `go-version-file: go.mod`.
- Go-based Docker build stages use the floating `golang:1.26-bookworm` image.
- User-facing documentation requires Go 1.26 or newer.

The latest stable Go 1.26 release is 1.26.5 according to the official Go downloads feed.

## Design

1. Change the `go` directive in `go.mod` from `1.26.1` to `1.26.5`.
2. Replace every active `golang:1.26-bookworm` build-stage image with `golang:1.26.5-bookworm` in:
   - `Dockerfile`
   - `Dockerfile.navarisd`
   - `Dockerfile.navarisd-firecracker`
   - `Dockerfile.test`
3. Leave GitHub Actions unchanged because its Go setup already reads the exact version from `go.mod`.
4. Leave `README.md` and `skills/navaris-getting-started/SKILL.md` at `Go 1.26+`; they describe the supported release line rather than the exact build patch.
5. Do not add a `toolchain` directive. The `go` directive and exact container image pins provide one clear version source per build environment without redundant version declarations.

Exact Docker pins make builds reproducible and keep container builds aligned with CI. Future patch upgrades must update `go.mod` and the Docker image references together.

## Dependency and Artifact Impact

No source, API, schema, dependency-version, or generated-artifact changes are intended. `go mod tidy` should not alter `go.mod` beyond the Go directive or change `go.sum`.

## Verification

1. Confirm all active Go version references resolve to 1.26.5 or the intentional user-facing `1.26+` requirement.
2. Run `go mod tidy` and verify it introduces no dependency changes.
3. Run the standard test suite: `go test ./...`.
4. Run build-tag variants used by supported providers:
   - `go test -tags incus ./...`
   - `go test -tags firecracker ./...`
   - `go test -tags 'incus firecracker' ./...`
5. Build the affected Docker targets when the local Docker environment is available; otherwise rely on the corresponding GitHub Actions builds and report that limitation explicitly.

## Rollback

Revert the `go.mod` directive to 1.26.1 and the Docker image references to `golang:1.26-bookworm`.

## Non-Goals

- Upgrading Go dependencies.
- Adopting Go 1.27 or prerelease toolchains.
- Changing application behavior.
- Changing release or CI workflow structure.
